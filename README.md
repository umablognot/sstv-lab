*[Türkçe README](README.tr.md)*

A browser-based **Robot36 SSTV** encoder and acoustic decoder. One device plays a photo as audio
tones through its speaker; another device listens with its microphone and rebuilds the image line
by line. The only link between the two devices is air — and as of v2, optionally a QR code stream,
a Bluetooth LE link or an NFC tap instead.

No app installation or account is required. Open the page on two devices and start with the
built-in test card, keeping the receiving microphone close to the speaker. Install it as a PWA and
everything — including all seven languages — works with **no internet at all**.

> **Privacy:** photos and microphone PCM never leave the device — encoding and decoding both run in
> the browser. On the official demo, additional requests update visit and reception-attempt counters;
> see **Live counters** below.

## What it actually does

| | |
|---|---|
| **Mode** | Robot36 (fixed — other modes are not auto-detected) |
| **Resolution** | 320 × 240, color |
| **Transmission time** | ~37 s per image (acoustic path) |
| **Audio band** | VIS 1100–1300 Hz; image 1500–2300 Hz; sync 1200 Hz |
| **Decoder sample rate** | Device rates above 16 kHz are resampled to 16 kHz |
| **Languages** | tr · en · de · es · fr · ar (RTL) · zh-CN |
| **Transfer channels** | Sound (acoustic) · QR code stream · Bluetooth LE (NUS) · NFC pairing |
| **Dependencies** | None at runtime. No build step, no CDN, no npm packages in the shipped app |

### Channel support matrix

| Channel | Sender needs | Receiver needs | Works offline |
|---|---|---|---|
| Sound | Any browser with audio out | Any browser with microphone + secure context | ✔ |
| QR code | Any browser (built-in encoder) | Camera + jsQR (any modern browser) | ✔ |
| Bluetooth | Chrome / Edge (desktop or Android) | Chrome / Edge with a Nordic UART peripheral | ✔ |
| NFC | Chrome on Android | Chrome on Android (or any NDEF tag reader phone) | ✔ |

## Use it

You need **two devices** — one to play, one to listen. This interface runs one role at a time;
use a second device for the acoustic demonstration.

1. **On the phone:** open the live demo → *01 Fotoğraf al* → **Mikrofonla dinlemeyi başlat**, allow
   microphone access.
2. **On the computer:** open the same page → *02 Fotoğraf gönder* → **Fotoğraf seç** (or press the
   colour-bar test card button if you do not want to pick a photo). You can also drag & drop or
   paste a photo.
3. Press **Sesi çal**. Hold the phone near the computer speaker.
4. Watch the image build over ~37 s. Save it with **PNG kaydet**.

**No second device handy?** Open *03 Kanallar* → **QR kod ile aktarım**: the test card (or your
selected photo) is streamed as QR codes; point another camera at it — or run the receiver on the
same tablet with a split window.

**Install for offline use:** open the page in Chrome/Edge on desktop or Android →
**Install app** (header button) or browser menu → *Add to Home Screen*. From then on the app opens
and works with Wi-Fi/cellular fully disabled.

**Tips that actually matter:**

- Keep both tabs in the foreground — browsers suspend audio in background tabs.
- Medium volume. Clipping distorts the FM deviation and wrecks the colour.
- Disconnect Bluetooth headsets for the *acoustic* path; their codecs mangle the tones. (For
  *playing* through a Bluetooth speaker, use the output picker in *03 Kanallar* instead.)
- Quiet room. Speech and music in the 1–2.5 kHz band land right on top of the signal.
- QR streaming: 20–40 cm distance, steady hands, ~400 ms per frame by default (adjustable).

## Languages & translations (`.po` / `.mo`)

The UI ships as standard GNU gettext catalogs:

```
dist/locales/
  tr/LC_MESSAGES/messages.po   ← source strings (reference set)
  tr/LC_MESSAGES/messages.mo   ← compiled, what the browser loads
  en/… de/… es/… fr/… ar/… zh-CN/…
```

- Strings live in the `.po` files; the browser loads the compiled `.mo`.
- Recompile after editing (no gettext installation required):

  ```bash
  npm run build:i18n     # node tools/msgfmt.mjs — .po → .mo for every language
  npm run check:i18n     # node tools/pocheck.mjs — key parity + app coverage gate
  ```

- **Add a language:** copy `dist/locales/en/LC_MESSAGES/messages.po` to
  `dist/locales/<code>/LC_MESSAGES/messages.po`, translate the `msgstr` values, then run
  `npm run build:i18n`. Add the code to `SUPPORTED_LANGUAGES` in `dist/i18n.js`, the
  `<select>` in `dist/index.html` and the `LANGUAGES` array in `dist/sw.js` so it gets
  precached. Right-to-left languages only need to be listed in `RTL_LANGUAGES` in `i18n.js`.
- Language detection order: `?lang=` URL parameter → visitor's saved choice → browser languages →
  English fallback. The `<html lang>` / `dir` attributes are updated automatically.

## Works offline (PWA)

- `manifest.webmanifest` defines icons (incl. maskable), theme colors and Receive/Send shortcuts.
- `sw.js` precaches the whole app on first visit: pages, styles, DSP code, the QR encoder, jsQR,
  icons and **all seven compiled language catalogs**.
- Strategy: cache-first with background refresh for same-origin GETs; navigations fall back to the
  cached `index.html`; the external counter API is passed through and simply stays silent offline.
- Serve over HTTPS (GitHub Pages is ideal). `http://127.0.0.1` also works for local development.

---

## Why HTTPS matters

`getUserMedia()` (microphone access) only works in a **secure context**:

- `https://…` — works (this is exactly why GitHub Pages is the right host)
- `http://127.0.0.1:5188` — works (localhost counts as secure)
- `http://192.168.x.x:5188` — **microphone blocked**

So on your LAN you can preview the page and *send* audio over plain HTTP, but a phone can only
*receive* over real HTTPS. Use the deployed Pages URL for phone testing.

## Live counters

The header shows two numbers, kept by [countapi](https://countapi.mileshilliard.com) on the
official demo only. They are approximate browser counts and reception attempts, not unique people.
They fail silently offline and never increment on forks or local previews.

                       # round-trip + i18n integrity + pocheck + counter tests
npm run test:acoustic  # full encode → WAV → acoustic decode simulation
npm run test:browser   # Playwright end-to-end (needs `npx playwright install`)
```

docs/                     ← GITHUB_ISSUE.md, CHANGELOG.md
```

### Testing highlights

- `tools/test-qr.mjs` rasterizes every generated QR matrix and decodes it back with the vendored
  jsQR — the encoder is verified against an independent decoder, including capacity tables
  (`v1-L = 17 B … v40-L = 2953 B`) and the chunked `SQ` framing.
- `tools/test-msgfmt.mjs` round-trips `.po → .mo → parse` for all seven catalogs.
- `tools/test-i18n.mjs` asserts 152 app keys × 7 languages with identical interpolation
  placeholders (`{rows}`, `{percent}`, …) everywhere.
- `tools/test-browser.cjs` drives a real Chromium through the full acoustic pipeline with a
  recorded WAV as the fake microphone, switches languages, streams QR frames and asserts zero
  page errors.

## Security & privacy notes

- Photos and microphone PCM are never uploaded; there is no analytics beyond the optional
  counter requests described above.
- The service worker only caches same-origin responses.
- Web Bluetooth requests are limited to devices advertising the Nordic UART service;
  Web NFC only writes/reads this app's own invite records.
- `test-output/` (fixtures, screenshots) is generated locally and git-ignored.
